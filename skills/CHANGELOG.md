# Changelog

## [Unreleased]

### Added

- `meshy-unreal`: a self-contained Unreal 5.9 Preview skill with 5.8 compatibility guidance,
  generation and local-edit routes, versioned MeshyTools, installer, revision ledger and
  opt-in editor smoke test. Imported from the `meshy-3d-agent` Unreal worktree with cookbook
  frontmatter metadata; the runtime and references retain their existing version and evidence.

### Changed

- **`meshy-unreal`**: hands prompt writing to the prompt-writing skills when they are installed beside it: `meshy-image-prompt` for concept and reference images, `meshy-text-to-3d-prompt` for Text to 3D previews, `meshy-texture-prompt` for refine, Image to 3D and Retexture textures, and `meshy-edit-prompt` for a part changed in the web app's Edit tool. Models, budgets, quotes, the ledger and Unreal paths stay with `meshy-unreal`; its own templates are the fallback. The text-to-prop refine template in `game-assets.md` now passes `--texture-prompt`. The quickstart, the editor-served `Skills/` folder note, the skills README and `AGENTS.md` say to install the prompt skills beside it.
- **`meshy-unreal`**: `game-assets.md` says to keep Rigging's default `skeleton_template` (`meshyrig`). Rigging gained `skeleton_template` and `include_fingers` on 2026-11-10; in a 2026-11-11 test on UE 5.9.0 a `ue5_mannequin` rig imported with bones below the pelvis 100 times too short, so it collapsed once animated, and it could not share the template's `SK_Mannequin` skeleton. `validation.md` records that test and two paid unattended Claude Code runs the same day: a chest prop (25 credits) and a knight set up as the Third Person player (29 credits), both through the image-first route with `meshy-image-prompt`.
- **`meshy-unreal`**: `setup.md`, `pipelines.md`, `delivery.md`, `troubleshooting.md` and `animation.md` resynced from `meshy-3d-agent`'s `meshy-3d-generation` references as of 2026-11-11. The Meshy CLI minimum is now 0.8.5, and a model from a description now starts by recommending a concept image for the user to approve, with Text to 3D as the quicker alternative; `SKILL.md` and `game-assets.md` follow. Sketches go through Image to Image, and shapes one picture cannot show go through multi-view images to Multi-Image to 3D. `CONTRIBUTING.md` records that these files are kept as exact copies.
- The skills are now part of the Meshy Cookbook, under `skills/`. Install by copying the desired skill directories into your agent's skills directory; the plugin manifests and marketplace wrapper have been removed. The repo checks are `scripts/skills/validate_skills.py`, which now also checks that every `check_prompt.py` copy matches `scripts/skills/check_prompt.py`.
- `meshy-text-to-3d-prompt`, `meshy-image-prompt` and `meshy-texture-prompt` link to the cookbook recipes that run the same tasks in code or with a coding agent.

### Removed

- **`meshy-image-prompt`**: a rig-file note and a quadruped rig test that relied on a parameter not on the Rigging docs page. Rigging is humanoid only, as its docs say. `meshy-edit-prompt` no longer says the API has no Edit endpoint "yet".

## [0.2.0] - 2026-11-08

### Changed

- **`meshy-image-prompt`**: the rig-ready character pipeline is now Text to Image with `pose_mode: "a-pose"` (9 credits), Image to 3D on Smart Topology (`model_type: "smart-topology"`, `ai_model: "meshy-t2.5"`, `target_polycount` 5,000 to 30,000, `texture_model: "meshy-7"`, `enable_pbr: true`, `texture_resolution: "2k"`, `pose_mode: "a-pose"`; 15 credits), then Rigging (5): 29 credits instead of 44. Tested live on 2026-11-08: one A-pose image went through Smart Topology with Meshy 7, Smart Topology with Meshy N1 and the earlier standard-plus-remesh route, and all three rigged and animated cleanly; the recommended arm had 31,472 triangles for a 30,000 target, no non-manifold edges, an 8.3 MB GLB and took 55 s, against 29 non-manifold edges, 12 MB and 127 s for the standard route, which stays documented as the alternative. `references/rig-ready-characters.md` has the comparison, what the rig files contain (a 0.01-scaled armature), the humanoid-only limit and the Resize settings for real size and a base pivot. Both meta prompts emit the new Image to 3D settings (the `image_to_3d` object in the code version has new keys). The `pose_mode` row now says the GPT Image models keep `aspect_ratio` and that only `nano-banana` and `nano-banana-pro` need a Pro plan for it. New "Smart Topology props" bullet with the 2026-11-08 prop and set-piece runs and `texture_model: "meshy-n1"` for an unlit look.
- **`meshy-text-to-3d-prompt`**: Smart Topology now names `meshy-t2.5` (100 to 30,000 faces, default 15,000, the default when `ai_model` is left out) beside `meshy-t2` (100 to 15,000, default 4,000); triangles only, `should_remesh` ignored, `quad` returns `400`. The skill now recommends Smart Topology for game assets and face budgets, as Meshy's model guide does, instead of only when the user names low-poly topology. The rigging limit is 380,000 triangles (remesh to 300,000 or less), not 300,000 faces. `meshy-t2.5` previews cost 5 credits. Meta prompts updated.
- **`meshy-texture-prompt`**: new "Which texture model" section: `texture_model` on Image to 3D (added 2026-11-03) and `ai_model` on refine and Retexture pick Meshy 7 (prompt, PBR, up to 8K), Meshy 6, Meshy 6 Lite or Meshy N1, which takes no prompt and returns `400` for `texture_prompt`, `enable_pbr: true`, `4k` and `8k`. The texture model does not change the price. Symptom table rows for a `400` with a prompt and for missing PBR maps.
- `check_prompt.py`: the low-poly hint names `meshy-t2.5`.
- `evals/evals.json`: the riggable-knight and treasure-chest assertions match the new settings and prices.
- README: 29-credit rig-ready character, the 2026-11-08 test, the Models docs page.
- All parameter ranges and prices were checked against the Meshy API docs (Image to 3D, Text to 3D, Text to Image, Models, Pricing, Rigging) and `openapi.yaml` on 2026-11-08.
- **`meshy-image-prompt`**: the model advice now comes from live tests of six more Text to Image models (2026-10-16, one sample per model): nano-banana, nano-banana-2, nano-banana-2-lite, gpt-image-2, gpt-image-2-5-flare and gpt-image-2-5-sunburst. `pose_mode: "a-pose"` gave a rig-ready A-pose on every model, and the GPT Image models followed the image formula most closely, so they now lead the list of models for final images. The 3-credit models drifted on the helmet prompt.
- **`meshy-image-prompt`**: prompts, the rig-ready pipeline and both meta prompts now default to `gpt-image-2-5-flare`, which works on every Meshy plan, instead of `nano-banana-pro`, which needs a Pro plan or above. The plan rules for `pose_mode` now match the docs: only a posed `nano-banana` request needs a Pro plan. The tested A-pose wording is included for anyone who prefers to write the pose in the prompt.
- **`meshy-edit-prompt`**: "How Edit works inside" is now "How Meshy reads the prompt" and explains what matters when you write a prompt: Meshy rewrites it based on the camera view and already keeps the rest of the model the same.
- Evidence files list the prompts, settings, run counts and results only; task ids and local file paths are gone.
- README: what you need before you start, where each prompt goes in the web app and the API, example requests, and a corrected Meshy Edit finding (naming the left shoulder put the raven on the left shoulder). Repo checks moved to `CONTRIBUTING.md`.
- **`meshy-text-to-3d-prompt`**: new "Props" section, based on six props run live on 2026-10-20 (a lantern, a chair, a longsword, a potted plant, a cottage and a cartoon van; one sample per arm). Before, the only prop tested was the knight's helmet. The formula held for each object's type and main parts, but the previews dropped a style that sets the whole look ("cartoon" gave a realistic van in 3 of 3), proportions, part counts and the size of a thin handle. Props whose look depends on these words are now sent to the image route; before, all props stayed on Text to 3D. Also new: leave out ground-level details on buildings (they came with an added ring of terrain), call holes "openings", and set `should_remesh` for real-time use (raw prop previews ran 47,000 to 2.2 million faces). Symptom table, meta prompts and evidence updated.
- **`meshy-image-prompt`**: new "Props" section from the same test. Image to 3D followed all six formula images, including spindles, a handle, a roof rack and leaves, so the thin-parts rule now targets dense clusters only. `aspect_ratio: "4:3"` for wide objects (at 1:1 a van was cut off). Clear glass came out as an open frame and frosted glass as solid panes. A thatched cottage came out at 7.7 million faces in a 303 MB GLB; with `should_remesh` and 30,000 faces it was 6.6 MB, at the same credits. Remesh is now recommended for game, web and AR use. The meta prompts pick the main object of a scene and leave out the ground around a building.
- `check_prompt.py`: preview prompts now flag ground-level details, cartoon or toy style words and "window panels"; image prompts flag clear glass.

## [0.1.0] - 2026-10-14

First release: four prompt-writing skills built from live A/B tests (Text to 3D, Text to Image, texturing and rigging on 2026-10-07, Meshy Edit on 2026-10-14).

### Added

- **`meshy-text-to-3d-prompt`**: the shape-only formula for the Text to 3D preview prompt; what to leave out (colors, materials, damage, pose, face count, scenes, thin parts, long lists) and the setting that replaces each; why rig-ready characters belong on the image route; remeshing at generation to stay under the 300,000-face rigging limit; symptoms and fixes; evidence; code and plain meta prompts; `check_prompt.py`.
- **`meshy-image-prompt`**: the Text to Image formula for images that convert cleanly to 3D; `pose_mode` versus pose words (equally clean, never both, never conflicting); `aspect_ratio`, `remove_background`, `generate_multi_view` and model costs; single image versus multi-view; the 44-credit rig-ready pipeline with rig measurements; evidence; meta prompts; `check_prompt.py`.
- **`meshy-texture-prompt`**: the style-then-part-by-part formula for texture and retexture prompts; specific hues over color families (saddle-brown 4 of 4, brown drifted grey); damage words that shift generic colors; ambiguous part names; no shape or lighting words; `enable_pbr`; symptoms and fixes; evidence; meta prompts; `check_prompt.py`.
- **`meshy-edit-prompt`**: the Meshy Edit formula (verb, part with its side, new part, details, what remains); the untextured-model requirement; what the lasso controls versus the prompt; why "keep everything else unchanged" is redundant; the 20-run results; `check_prompt.py`.
- `scripts/check_prompt.py` (one copy per skill): a prompt checker for length, material and color words, pose conflicts, missing framing phrases, generic hues, shape words in texture prompts and unsided parts in Edit prompts.
- Repo checks (`scripts/validate_skills.py`) and trigger evals (`evals/trigger/`), described in `CONTRIBUTING.md`.
